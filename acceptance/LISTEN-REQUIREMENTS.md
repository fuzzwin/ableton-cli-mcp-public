# Silent internal listen/review v1 (frozen before implementation)
Outcome: a callable CLI/MCP file-only review mode that helps an agent understand bounced audio through signal evidence, without claiming perceptual hearing.
1. Production.listen(plan_path), CLI production listen PLAN and workspace-only MCP ableton_listen accept an explicit plan. No output device, transport, network, plugin loading or source edits. Without workspace the new tool is absent.
2. Plan schema: source relative audio required; optional reference relative audio, bpm 40..240 (explicit hint only), sections up to24 {name,start,end} ordered/nonoverlapping, stems up to4 {name,path,role,monophonic?}, focus subset balance/dynamics/rhythm/melody/space/arrangement. Unknown fields/types, bool-numbers, nonfinite/out-of-duration/overlapping sections, escaping paths and mismatched stem sample rate/frame count fail clearly before successful evidence. All referenced paths validated before analysis.
3. Source whole-file measured metrics reuse audio analyzer. Sections (default8second windows) include actual timestamps, RMS/peak/crest, spectral centroid, stereo/mid/side, onset count/rate and optional nearest-sixteenth timing deviations using declared bpm and time zero. Silence inside valid tracks is finite and explicitly labelled. Section energy/brightness changes are measured observations, never musical diagnoses.
4. Pitch/melody diagnostics only for explicitly monophonic lead/bass stems, not full mixes: bounded 8kHz autocorrelation, confidence/voiced coverage, range, pitch-class histogram and at most128 estimated note spans. Known steady synthetic A4 with silence and changed notes is estimated within1semitone; rests do not count as voiced. No key/correct melody claim, no tuning correction on a mix. Polyphony, distortion, slides and reverb can invalidate pitch estimates.
5. Optional reference metrics are explicitly level-matched diagnostics, without artist imitation or quality-ranking. Observations are separate from proposed actions and limitations; creative_acceptance remains pending, perceptual_listening false, speaker_playback false. No numerical quality score or fabricated user preference.
6. New unique review.json with exact source/reference/stem hashes, report schema version, plan/analysis assumptions, limits, recorded local review event and progress stages. Report has bounded size, JSON finite; source bytes preserved. Recall retrieves measured review separately from human feedback. All runtime reports/audio/URLs remain ignored.
7. Validate with known synthetic audio (silence passages, notes/rhythm/balance), error cases and real120second song(s). Existing114 core checks must pass with only intentional new tool count expectation. Actual pinned Proof Loop uses frozen tests and fresh run ID; report formal acceptance truthfully. At most2repair rounds; independent review is advisory, same account custody limit.
